# AGENT.md — 일산 호수공원 가족 산책 지도 MVP 작업 규칙

## 1. 프로젝트 목표
- 일산 호수공원 인근 아이 동반 가족을 위한 주말 반나절 산책 지도 MVP를 개발한다.
- 핵심 기능은 장소 마커 클러스터, 추천 산책 경로, QR코드 공유다.
- 먼저 장소 탐색형 MVP를 구현하고, 연령·산책 시간별 개인화는 후속 단계로 둔다.
- 사용자에게는 이해하기 쉬운 한국어로 간결하게 설명한다.

## 2. 작업 시작 전 필수 절차
1. 현재 작업 폴더와 하위 구조, 기존 파일, `package.json`, 관련 문서를 먼저 확인한다.
2. 작업 전에 **생성할 파일과 수정할 파일 목록**, 변경 목적을 사용자에게 알린다.
3. 이미 존재하는 파일은 통째로 덮어쓰지 않고 필요한 부분만 최소 범위로 수정한다.
4. 변경 후 어떤 파일에서 무엇을 왜 바꿨는지 간략히 설명한다.
5. 프로젝트 폴더나 소스가 제공되지 않았다면 임의로 프로젝트가 있다고 가정하지 않는다.

## 3. 사용자 승인 필수 작업
- **파일 삭제**, **`git push`**, **배포**, **패키지 대량 추가·업그레이드·삭제**는 사전 승인을 받아야 한다.
- 명시적 승인 없이 위 작업을 실행하지 않는다.
- 기존 데이터의 대량 교체 또는 파괴적 마이그레이션도 실행 전에 확인한다.

## 4. 보안 및 환경 변수
- API 키, 비밀번호, 토큰, 인증 정보를 소스코드·문서·로그·예제에 직접 쓰지 않는다.
- 로컬 비밀값은 `.env.local`로 관리하고, `.env.example`에는 **실제 값 없는 변수명과 빈 예시**만 기재한다.
- `.env.local`이 버전 관리에 포함되지 않는지 확인하고, 사용자에게 설정 방법을 안내한다.

## 5. 장소·좌표 데이터 원칙
- 사용자가 제공하지 않은 **장소, 주소, 영업시간, 좌표, 방문 통계, 소요 시간**을 만들어내지 않는다.
- 미확인 값은 공란(`null`, 빈 셀) 또는 UI에서 `확인 필요`로 표시한다.
- 제공된 좌표도 확정/주소 기반 추정/미검증 상태를 구분하고, 근거 없는 보정을 하지 않는다.
- 지도 라이브러리 설정, GeoJSON 좌표, 경로 배열은 **`[longitude, latitude]` = `[경도, 위도]`** 순서다.
- CSV는 **`latitude`(위도), `longitude`(경도)** 컬럼 이름을 각각 사용하며 위치를 바꿔 쓰지 않는다.
- 위도·경도가 비어 있으면 지도 마커나 경로에 임의 좌표를 대체하지 않는다.
- 경로의 이동 거리나 시간을 검증하지 않았다면 확정 수치처럼 표시하지 않는다.
- 장소별 출처·라이선스·검증 상태를 가능한 한 보존한다.

## 6. 구현 범위와 품질
- 기존 기술 스택과 코딩 스타일을 우선한다. 임의로 프레임워크를 교체하지 않는다.
- 마커 클러스터, 테마별 장소 필터, 추천 코스 확인, QR 공유의 핵심 이용 흐름부터 구현한다.
- 아이 동반 가족이 이해하기 쉬운 문구와 모바일 접근성을 우선한다.
- 지도에서 장소가 표시되지 않는 경우 오류를 숨기지 말고 원인(좌표 없음 등)을 알린다.
- 변경 사항을 최소화하고, 가능한 경우 관련 기능을 검증한다.

## 7. 작업 종료 전 검사 및 보고
프로젝트 루트에 `package.json`과 해당 스크립트가 있는지 확인한 뒤 아래 명령을 **각각 실행**한다.

```bash
npm run typecheck
npm run lint
npm run build
```

- 실행한 명령별로 **성공/실패 결과를 그대로** 보고한다.
- 실패 시 오류 메시지의 핵심과 원인을 숨기지 않는다.
- `package.json`, 스크립트 또는 npm 실행 환경이 없어 실행할 수 없으면 **미실행(이유 포함)**으로 구분해 보고한다. 성공했다고 쓰지 않는다.
- 최종 보고에 변경 파일 목록, 변경 이유, 검증 결과, 남은 확인 사항을 포함한다.
